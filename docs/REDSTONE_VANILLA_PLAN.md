# Vanilla-Exact Redstone Acceleration — Campaign Plan

Цель: ускорить ванильный редстоун-провод **с точным сохранением ванильной
семантики, включая порядок обновлений** (locational behavior, QC,
0-tick — всё, на чём живут технические фермы). Это принципиально
отличается от Alternate Current: AC меняет порядок обновлений
(Ferrite честно держит его default-off ровно поэтому).

## Чему научил Ferrite (изучен 2026-06-11, клон в ~/IdeaProjects/FerriteStudy)

1. **Per-update FFI-диспатч = смерть.** Их замер: 57K JNI-вызовов/тик
   на lag-machine → в 10× медленнее ванили. Вывод: батчить per-cascade.
   У нас nalim (~1 ns/вызов против их ~150 ns JNI) — ограничение мягче,
   но форма та же: один вызов на каскад.
2. **Zero-copy handoff** — статические direct-буферы, разрешаемые в
   указатель один раз; Rust читает на месте. У нас уже так (nalim +
   DirectByteBuffer addresses), плюс мы без JNIEnv-обвязки вообще.
3. **Oracle-методология** — их сильнейшая практика: shadow-валидатор,
   150K+ автоматических сравнений с ванилью до включения по умолчанию.
   Берём и усиливаем: они сверяли **финальные состояния**, мы будем
   сверять **полную последовательность событий** (порядок!).
4. Их AC-порт нам не подходит по определению задачи (см. цель).

## Анатомия ванили 26.1.2 (исходники извлечены)

`net.minecraft.world.DefaultRedstoneController.update()` (yarn) /
`DefaultRedstoneWireEvaluator` (mojmap) — тело одного шага:

```
target = max(strongPower(pos), maxNeighborWire(pos) - 1)   // ~25 чтений блоков
if (state.POWER != target):
    setBlockState(pos, POWER=target, NOTIFY_LISTENERS)      // промежуточное значение!
    toUpdate = HashSet{pos} ∪ {pos ± 6 направлений}          // ХЭШ-ПОРЯДОК ИТЕРАЦИИ
    for p in toUpdate: world.updateNeighbors(p, wire)        // рекурсия каскада
```

Ключевые факты:
- **Каскад** = рекурсия через neighborUpdate соседних проводов; провод
  обновляется многократно за каскад, пока сеть релаксирует (до ~15 раз).
  Доминирующая стоимость: ~25 чтений block state на КАЖДЫЙ шаг.
- **Ванильный порядок** = композиция из (а) hash-порядка итерации
  `Sets.newHashSet()` по 7 позициям — чистая функция координат
  (BlockPos.hashCode + механика таблицы java.util.HashMap при capacity 16,
  insertion: pos, затем Direction.values()); (б) фиксированного порядка
  направлений внутри `updateNeighbors`. Оба ДЕТЕРМИНИРОВАНЫ и
  воспроизводимы в Rust бит-в-бит. Это и есть locational behavior.
- Каскад по чисто-проводной сети — **чистая функция** от: топологии сети,
  внешних strongPower-входов на каждой позиции, и порядковых правил выше.

## Архитектура: Cascade Replay Engine

Та же философия, что спасла cramming: **Rust считает, ваниль применяет.**

1. **Вход в каскад** (mixin на контроллер-поле RedstoneWireBlock —
   Ferrite доказал этот seam): walk замыкания проводной сети от стартовой
   позиции (по правилам связности calculateWirePowerAt, включая
   диагонали через solid-блоки) + чтение strongPower каждой позиции.
   Сеть пересекает границу незагруженного чанка → bail в ваниль.
2. **Rust-ядро**: точный реплей ванильного алгоритма на компактном
   графе — те же рекурсии, тот же hash-порядок, та же релаксация.
   Целочисленные операции над массивом вместо 20K+ чтений block state.
   Выход: упорядоченный список событий
   `[SetWire(pos, power) | UpdateNeighbors(center)]`.
3. **Эмиссия в Java**, по списку, в точном порядке:
   - SetWire → setBlockState(NOTIFY_LISTENERS) — промежуточные значения
     видны синхронным читателям, как в ванили;
   - UpdateNeighbors → world.updateNeighbors(center, wire), при этом
     neighborUpdate ПРОВОДОВ нашей сети подавляется thread-local флагом
     (их эволюция уже в скрипте; не подавлять = пересчёт от
     промежуточного состояния мимо скрипта);
   - **Mutation-abort**: если во время эмиссии кто-то (рельса, TNT,
     поршень-голова...) синхронно изменил блок в/рядом с сетью —
     остаток скрипта отбрасывается, каскад довершает ваниль от текущего
     состояния. Консервативно = корректно.
4. **Fallback везде**: любой bail (незагруженный чанк, переполнение,
   мутация, выключенный флаг) → нетронутая ваниль.

### Синхронные читатели (анализ)

Безопасны (реагируют scheduled tick'ом, читают ПОСЛЕ каскада):
компаратор, репитер, observer, факел, диспенсер/дроппер.
Синхронно читают/мутируют в neighborChanged: **поршень (checkIfExtend —
читает, schedule'ит), рельсы (мутируют shape!), TNT (мутирует!), двери,
лампа (включение синхронно)**. Чтения — корректны при нашей эмиссии
промежуточных состояний; мутации — ловит mutation-abort.

## Фазы

- **R0 — Oracle first.** Mixin-рекордер на DefaultRedstoneController.update:
  пишет (снапшот сети на входе; последовательность событий) в ring-лог.
  Поведение не меняется. Это и генератор фикстур для unit-тестов ядра,
  и каркас live shadow-валидатора.
- **R1 — Ядро.** Rust-реплей: воспроизведение BlockPos.hashCode +
  HashMap-итерации (версионно-locked — выделить в отдельный модуль с
  тестами!), релаксация, эмиссия событий. Unit-тесты: реплей фикстур R0
  бит-в-бит (последовательности равны).
- **R2 — Shadow mode.** Живая интеграция за флагом: ядро считает
  СПЕКУЛЯТИВНО, исполняет по-прежнему ваниль, последовательности
  сравниваются, расхождения в лог. Гоняем на тест-сервере на реальных
  контрапшенах.
- **R3 — Flip.** Включение реальной эмиссии после N часов сухого
  shadow-лога. Порог маленьких каскадов (как у Ferrite: на 1 репитер +
  короткий провод setup-cost ядра не окупается — оставлять ваниль при
  размере сети < порога).

## Связь с регионами (Tier-0 уже в проде)

Каскады локальны → регион-аффинность естественна: ядро зовётся на
воркере региона, скрипт каскада не пересекает claim. Block-event
очереди и так регионализованы в Fabrolia. Phase R2+ просто наследует
это бесплатно.

## Риски

- Механика HashSet-порядка — версионно-хрупкая (capacity/hash mixing
  меняются между JDK? java.util.HashMap spread() стабилен с JDK 8;
  BlockPos.hashCode — из исходников MC). Изолировать + тестировать
  против R0-фикстур, никогда против «теории».
- Сети >2GB-каскады/гигантские замыкания: cap размера сети → bail.
- Параллельные каскады разных регионов на смежных сетях — claim'ы
  Fabrolia сериализуют внутри региона; межрегиональные провода — через
  существующие vanilla-пути (bail при пересечении границы региона в v1,
  ослабить позже).


## R1 — ВЫПОЛНЕНО (2026-06-11)

`native/src/util/redstone/sim.rs` — симулятор каскада из трёх столпов
(power-math DefaultRedstoneController + jorder 7-pos HashSet + collector
queue discipline). **498 записанных каскадов лаг-машинки (480 проводов)
реплеятся бит-в-бит**, включая 43916-событийный (ваниль 15.38 мс → чистый
сим 1.386 мс, ×11). Граф/sp заморожены легально: SET меняет только POWER,
вся реактивщина в ванили отложенная.

Открытие R1: ДВЕ дисциплины входа в каскад —
* **InDrain** — эвалюатор вызван диспатчем внутри работающего дрейна
  (рычаг → SixWay → провод): 7 updateNeighbors уходят в pending пачкой;
* **Depth0** — прямой вызов на глубине 0 (постановка/снятие пыли →
  onBlockAdded): каждый updateNeighbors = собственный addAndRun с
  немедленным дрейном, диспатчи интерливятся между UPD.
Фикстуры режим не пишут — тест определяет адаптивно (rollback сети);
продакшен-миксин просто читает глубину живого коллектора.

R2 next: in-game takeover — mixin на первом wire-EVAL бурста: Java строит
снапшот сети (walk по правилам calculateWirePowerAt), сим выдаёт скрипт,
Java исполняет SET (setBlockState flags=2 — пакеты/шейпы/обсерверы сами) +
UPD только на не-проводные таргеты (SixWay с wire-skip), mutation-abort при
любом sync-setBlock со стороны, shadow-режим до флипа.
