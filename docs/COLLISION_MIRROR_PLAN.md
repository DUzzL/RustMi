# Block-Collision Mirror — Campaign Plan (Tier-2)

Цель: срезать доминирующий кусок тика толпы — `BlockCollisions` свип в
`Entity.move()` (54% воркер-времени / ~14 мс на сцене 1816 мобов,
jstack-burst 2026-06-11) — **с бит-в-бит ванильной резолюцией**.

Методология та же, что у cramming v3 и редстоуна: сначала ground truth,
потом ядро; Rust считает только то, что детерминированно специфицировано;
любое сомнение → ванильный фоллбек на этот вызов.

## Точка перехвата

`Entity.collideBoundingBox(@Nullable Entity, Vec3 delta, AABB box, Level,
List<VoxelShape> entityShapes)` — статическая резолюция одного бокса против
мира. Вызывается 1–3 раза за move (основной + step-up варианты) из
`Entity.collide`, который сам владеет step-логикой — её НЕ трогаем.

## Фазы

- **C0 — рекордер (готов, 2026-06-11).** `/rustmi collision record on`.
  Классификация каждого вызова по ванильным правилам обхода (swept =
  `box.expandTowards(delta)`; курсор `floor(min−1e-7)−1 .. floor(max+1e-7)+1`;
  ±1 ring посещается только для `hasLargeCollisionShape`; unloaded chunk →
  скип; `CollisionContext.of(entity)`): **simple** (воздух + полные кубы,
  без entity-шейпов, без бордера) / complexBlock / entityShapes / border /
  huge. Счётчики вызовов И наносекунд по категориям → потолок выигрыша виден
  из `status` напрямую. Simple-свипы с солидами пишутся как JSON-фикстуры
  (box, delta, solids[], result) в `rustmi-collision-fixtures/`, cap 400.

- **C1 — бит-в-бит ядро юнит-кубов (Rust).** Порт ванильной
  `Shapes.collide(axis, box, shapes, delta)` для случая «все шейпы — полные
  кубы на блок-позициях»: точный порядок осей Y→X→Z из `collideWithShapes`,
  epsilon-семантика 1e-7, та же арифметика double. Тесты = фикстуры C0,
  сравнение бит-в-бит (assert_eq на все три компоненты). НЕ выпускается в
  игру до зелёных фикстур.

- **C2 — секционное зеркало + live-флип.** Per-`LevelChunkSection` нативный
  снапшот: 4096 × 2-бит класс (EMPTY / FULL_CUBE / COMPLEX) + seq-версия.
  Ленивая сборка при первом касании, инвалидация миксином на
  `LevelChunkSection.setBlockState` (bump версии; читатели сверяют до/после —
  seq-lock, расхождение → фоллбек этого вызова). Entry-условие фаст-пас:
  swept box весь в зеркалированных секциях, все inner-клетки EMPTY/FULL,
  ring без large-шейпов (зеркалу нужен и бит has-large), entityShapes пуст,
  бордер далеко. Иначе — ваниль. Shadow-режим перед флипом: Rust и ваниль
  считают параллельно, расхождения в лог, применяется ваниль; флип только на
  сухом логе (как redstone R2→R3).

- **C3 — расширения по профилю.** Partial-шейпы как списки AABB в зеркале
  (плиты/ступени дают огромную долю реальных миров); entity-шейпы
  (лодки/шалкеры = AABB) прямо в солвер; переиспользование зеркала для LoS
  (sensors), pathfinding, снарядов — это и есть «block mirror» инфраструктура.

## Известные ловушки

- Шейп зависит от `CollisionContext` (порошковый снег: тип моба/ботинки;
  леса; и т.п.) → такие стейты в зеркале всегда COMPLEX → ваниль.
- Мид-тиковые изменения блоков (зомби ломают двери, эндермены) — закрыто
  seq-версией секции; пропуск инвалидации = неваниль, поэтому мутационный
  мискин обязан покрыть ВСЕ пути записи в секцию (setBlockState — единая
  воронка).
- `getChunkForCollisions` null (unloaded) — ваниль скипает клетки; зеркало
  обязано воспроизводить (нет секции в зеркале → этих клеток нет).
- Результат должен совпадать бит-в-бит, включая знаки нулей? — фикстуры
  покажут; если ваниль производит -0.0, повторяем.
