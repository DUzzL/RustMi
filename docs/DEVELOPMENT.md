# Rustmi development guide

Rustmi is a server-side Fabric mod for Minecraft 26.3 (Java 25) that moves hot vanilla
paths — block collision, entity cramming and sensors, explosions, redstone wire, block
storage, spawn caps — into a Rust library while keeping vanilla results bit for bit. One
jar carries the library for six platforms and calls it through Nalim (JVMCI) or the FFM
API. It runs on a ~35-player production server next to Fabrolia (`../Fabrolia`).

## The contract

- **Vanilla parity.** Every optimization must give exactly vanilla's result, including
  order (entity iteration, update order, RNG draws). When a precondition cannot be proven
  for a call, that call runs vanilla. Speed bought by approximating vanilla is a bug.
- **Fail loud.** Startup failures stop the server with the cause (`RustmiMixinPlugin`
  turns exceptions into `Error`); engines that hit an exception disable themselves and log.
  Fix causes; keep vanilla fallbacks, never silence a mismatch.
- **Proof.** A change to runtime code is proven by the parity harness printing
  `METRIC vanilla_failures=0` for both backends, plus the shadow mode of the feature
  touched (see `docs/CODEMAP.md`). Performance claims compare `perf_mspt` of two harness runs.

## Layout

| Path | What |
|---|---|
| `src/main/java/com/github/tatercertified/rustmi/` | startup: mixin plugin, native extraction, Debugify canceller |
| `src/main/java/com/github/tatercertified/nalim/` | every feature, mixins, `/rustmi` commands, backend selection. The package name is historical; it is not the Nalim library |
| `src/main/resources/` | `fabric.mod.json`, `rustmi.mixins.json`, `rustmi.accesswidener` |
| `native/` | Rust cdylib; `native/lib.h` is generated by cbindgen on every cargo build and committed |
| `fixtures/` | recorded vanilla data for the Rust tests (collision, redstone) |
| `gradle/natives.gradle`, `gradle/native-bindings.gradle` | cross-build of the library; generation of `RustmiLib`/`FfmBindings` |
| `libs/` | `nalim.jar` (from `../nalim`) and `fabrolia-compile.jar`, pinned by SHA-256 in `build.gradle` |
| `tools/parity/` | parity/perf/RAM harness; `tools/setup-toolchain.sh` |
| `docs/CODEMAP.md` | feature → mixins → engine → Rust module → checks, and each feature's vanilla rules |
| `stand/`, `release/` | not in git: harness server and runs; released jars with `SHA256SUMS` |

## Build and test

The build and the harness need a Linux host (WSL2 works); the scripts use GNU tools.

```bash
tools/setup-toolchain.sh                 # once: rustup targets, cargo-zigbuild, zig 0.14.1
export JAVA_HOME=/path/to/jdk-25
./gradlew build                          # jar: build/libs/rustmi-<version>.jar
```

`build` cross-compiles the library for all six targets (cached after the first run), packs
it with SHA-256 files, and runs `check`: the Java test mains in `src/test`, `cargo test`,
and `NativeBindingsContractTest`; so `test`/`check` need the toolchain too. zig comes from
`$ZIG`, `~/.local/opt/zig-0.14.1/zig` or `PATH`; tested with 0.14.1, and 0.16 cannot link the
macOS libraries.

## Verify at runtime

```bash
tools/parity/setup.sh                    # once: stand/ with a 26.3 server, Lithium, Fabric API, Fabrolia
tools/parity/harness.sh                  # ~5 min; prints METRIC vanilla_failures=0 … ASI failures={}
RUSTMI_BACKENDS=ffm tools/parity/harness.sh   # one backend only
```

`setup.sh` takes the Fabrolia jar from `../Fabrolia/release/` or from `FABROLIA_JAR`
(`libs/fabrolia-compile.jar` is the full 0.2.38 release jar). The harness builds the jar,
records vanilla (`ref-V`) and Lithium+Fabric API+Fabrolia (`ref-L`) references (regenerated
when the server, stack jars or `drive.py` change), then runs Rustmi with each backend forced
(`R-<backend>`, `LR-<backend>`): worldgen and a redstone contraption compared section by
section, every shadow mode, `wirecheck`, perf and RAM. Logs: `stand/logs/`; per-run data:
`stand/runs/*/result.json`. `tools/parity/ab.py` toggles features on a crowd workload for
A/B timing.

## Native surface

- Declare a function once in `src/main/java/.../nalim/rust/NalimBindings.java`:
  `@Link(name = "oxi_…") public static native <type> name(<params>);` with only
  `int`/`long`/`double`/`float`/`byte`/`short` (and `void` returns); pointers are `long`
  addresses, widths must match `lib.h` exactly. Other shapes fail the build.
  Callers use `RustmiLib.name(...)`; the build regenerates the facade and FFM bindings.
- `@Critical` (FFM call without a thread-state transition) only for short, bounded functions
  that never wait on a lock another call may hold long; everything else stays plain.
  Under Nalim every call behaves like a critical one.
- Rust exports are `#[no_mangle] pub extern "C"`; `cargo build` rewrites `native/lib.h`,
  commit it with the change so the ABI diff is reviewable.

## Backends

`NativeBackend.select` picks once at startup (log line `RustMI native backend: …`,
`/rustmi stats`):

- **Nalim** when Linux x86_64, Java 25–26, HotSpot C2 (not GraalVM), G1/ZGC/Serial/Parallel,
  and the launch has `--add-modules=jdk.internal.vm.ci` (Java 26+: also
  `-XX:-UseCodeCacheFlushing`).
- **FFM** otherwise (`--enable-native-access=ALL-UNNAMED` silences the JDK warning).
- `-Drustmi.backend=nalim` fails startup instead of falling back; `=ffm` forces FFM.

## Gotchas

- Fabrolia couples both ways; keep these names or change both projects together:
  - Fabrolia calls `com.github.tatercertified.nalim.sort.DistanceSort.sort` by name
    (`DistanceSortBridge`) and Rustmi registers `RustLocalCapProvider` with its `LocalCapBridge`.
  - Rustmi compiles against Fabrolia's `regions.{Region,RegionGrid,RegionScheduler,
    RegionTickHooks,RegionWorkerThread}`, `SensorCandidateBridge`, `LocalCapBridge` from
    `libs/fabrolia-compile.jar`, and reflects on `ParallelProcessor.executor` /
    `pumpUntilDone`. When Fabrolia is absent or its API differs (a `LinkageError` at the
    first tick), Rustmi logs it and uses its own non-regional paths. Ship a Rustmi built
    against the Fabrolia that runs next to it.
- `tools/parity/drive.py` parses `/rustmi … status` lines with regexes; change their wording
  together with the harness.
- Main code compiles with `--release 17` to match the mixins' `compatibilityLevel`; only the
  generated FFM source set uses 25. The mod still requires Java 25 (Gradle toolchain = 25).
- `RustmiMixinPlugin.onLoad` runs before Minecraft classes are transformed. Code reachable
  from it (`LoadRustBinary`, `NativeBackend`, `CrammingHooks.register`,
  `SpawnCapHooks.register`) must not make the JVM load a `net.minecraft` class, or Mixin
  fails with "target was loaded too early"; keep MC-typed work behind the first tick.
- `fabric.mod.json` `lithium:options` are parity settings (`math.sine_lut`) and a native
  sections requirement (`chunk.serialization`); `DebugifyMixinCanceller` keeps vanilla sin/cos.
- macOS builds use the system allocator (mimalloc needs SDK headers zig lacks).
- The Windows, macOS and Linux arm64 libraries are cross-built but have never run on real
  machines; only Linux x86_64 is verified live.

## Updating pinned jars

- `libs/nalim.jar`: build in `../nalim` (`./build.sh`), copy `nalim.jar`, update its SHA-256
  in `build.gradle` (and the version string there if `../nalim/fabric.mod.json` changed).
- `libs/fabrolia-compile.jar`: copy a Fabrolia fabric jar
  (`../Fabrolia/release/fabrolia-fabric-*.jar`), update its SHA-256 in `build.gradle`, build.

## Release and install

1. `./gradlew clean build` (one jar in `build/libs`, which the harness needs) and
   `tools/parity/harness.sh` with `vanilla_failures=0`.
2. Copy `build/libs/rustmi-<version>.jar` to `release/`, `sha256sum *.jar > SHA256SUMS`
   there, and move the tag: `git tag -fa prod/current -m "<version>"`.
3. Install with the server stopped: replace `mods/rustmi-*.jar` (and remove any old
   `rustmi-nalim-*`/`rustmi-panama-*` jar; the mod refuses to start next to them). Launch
   flags for Nalim are in the Backends section.

## Git

Branch `main`; tag `prod/current` = the commit of the jar in `release/`. Remote `origin`
is this fork (DUzzL/RustMi), and `main` tracks `origin/main`. Remote `upstream` is the
original project (Tater-Certified/Oxidizium) with pushing disabled; this fork has never
been pushed there.

## Known open items

- Redstone fixture recorder and R2 shadow are reachable only through their config files.
- `oxi_redstone_entry` saves the network powers on every call for `oxi_redstone_undo`,
  which only the R2 shadow uses.
- Spawn-cap near-player set assumes view distance ≥ 8 chunks.
- License: `LICENSE.txt` (MIT) covers the original project; `LICENSE-GPL-3.0.txt` came with
  the former `nalim/` module (`com.github.tatercertified.nalim.*`). `fabric.mod.json` says MIT.
